# A1 Burger & Best Fried Chicken — Electronic Menu & Order System

موقع ومنيو إلكتروني متكامل وتفاعلي فخم لمطعم **A1 Burger — Best Fried Chicken** مستوحى بالكامل من هوية اللوجو العريقة (Gentleman Vintage Diner)، مخصص للموبايل والكمبيوتر، يتيح للعملاء تصفح الوجبات، تخصيص الأصناف، وإرسال الأوردر بدقة عبر واتساب مع ترقيم يومي تسلسلي ذري يبدأ من #1 يومياً بتوقيت القاهرة عبر Firebase Firestore، بالإضافة إلى لوحة تحكم إدارية خاصة للمطعم بحساب جوجل.

## 1. Overview & Core Concept

- **طبيعة المنصة**: منيو إلكتروني سريع جدًا بتجربة مستخدم مدروسة (Mobile-First)، يعرض جميع أقسام المطعم (وجبات الكرسبي، وجبات الدجاج، المقبلات والإضافات، الصوصات، ماك آند تشيز، وساندوتشات البرجر والدجاج).
- **الجمهور المستهدف**: عشاق الفرايد تشيكن والبرجر في مصر الباحثين عن تجربة طلب فورية بدون تعقيدات وتطبيق ثقيل.
- **القيمة المضافة**: طلب فوري بضغطة زر ينسق رسالة واتساب معتمدة ومحسوبة مع رقم أوردر تسلسلي رسمي يومي يُسجل في قاعدة البيانات، مع دعم التيك أواي والدليفري.

## 3. Key Product Decisions & Trade-Offs

- **الترقيم اليومي الذري (Daily Atomic Counter)**:
  - *القرار*: استخدام مستند عدّاد يومي في Firestore تحت المسار `/daily_counters/{YYYY-MM-DD}` بتوقيت القاهرة (`Africa/Cairo`).
  - *السبب*: منع تكرار أرقام الأوردرات في حال طلب أكثر من عميل في نفس الثانية، وبدء العد التلقائي من #1 بعد منتصف الليل كل يوم.
- **الطلب المباشر عبر واتساب**:
  - *القرار*: فتح رابط `wa.me/201055450417` مع رسالة منسقة بالكامل تحتوي على رقم الأوردر، نوع الطلب، الأصناف، والعنوان والملاحظات.
  - *السبب*: سرعة تأكيد الطلب للعميل بدون وسيط وتوافق مع سلوك الشارع المصري.
- **لوحة التحكم (/admin)**:
  - *القرار*: صفحة إدارة خاصة لمتابعة الأوردرات اليومية، تغيير حالات الطلب (جديد / قيد التحضير / تم التوصيل)، واحتساب إجمالي المبيعات وعدد الأوردرات، محمية بـ Google Sign-In المعتمد لمالك المطعم.

## 4. Technical Architecture & Data Strategy

### هيكل البيانات في Firebase Firestore

```
firestore
├── daily_counters/{date_string}
│     └── lastOrderNumber: number (atomic increment)
│
├── orders/{orderId}
│     ├── orderNumber: number (e.g. 12)
│     ├── dateString: string (e.g. "2026-10-29")
│     ├── createdAt: timestamp (serverTimestamp)
│     ├── orderType: "delivery" | "takeaway"
│     ├── customer: { name, phone, address?, landmark?, notes? }
│     ├── items: [ { id, name, size?, quantity, price, totalPrice, notes? } ]
│     ├── deliveryFee: number
│     ├── totalAmount: number
│     └── status: "new" | "preparing" | "completed" | "cancelled"
│
└── settings/restaurant
      ├── deliveryFee: number (default: 20)
      ├── isOpen: boolean
      └── minOrderAmount: number
```

### مخطط المكونات البرمجية

```
┌─────────────────────────────────────────────────────────────┐
│                       App Container                         │
├─────────────────────────────────────────────────────────────┤
│  • WelcomeSplash (شاشة البداية مع اللوجو ودخول متحرك)        │
│  • TopBar / Header (اللوجو، اسم A1، زر الاتصال، وحالة السلة)  │
│  • CategoryRibbons (شريط الأقسام الأفقي القابل للتمرير)       │
│  • MenuSearch & Filters (بحث سريع في الأصناف والمكونات)      │
│  • ProductGrid & ItemCard (كروت الأصناف وسعرها وحالتها)     │
│  • ProductBottomSheet (اختيار الحجم، الخيارات، الملاحظات)     │
│  • CartDrawer (تعديل السلة، اختيار تيك أواي/دليفري، والفورم) │
│  • OrderSuccessModal (عرض رقم الأوردر وزر المتابعة)          │
│  • AdminDashboard (/admin) (لوحة متابعة وإحصائيات المبيعات) │
│  • RestaurantFooter (بيانات المطعم، العنوان، وفيس بوك)       │
└─────────────────────────────────────────────────────────────┘
```

## 5. خطة العمل المباشرة بعد الاعتماد

1. تفعيل تكامل Firebase عبر الأداة المخصصة وإنشاء قواعد البيانات وأمان Firestore.
2. بناء المكونات الأساسية وتنسيق الهوية البصرية والألوان العنابية والفحمية.
3. إدراج جميع أصناف المنيو الستة بدقة كاملة مع أسعارها وخياراتها (سنجل/دبل، سادة/شيتوس، أحجام الصوصات).
4. برمجة عدّاد الأوردرات اليومي الذري ومنطق إرسال رسائل واتساب المنظمة.
5. تطوير لوحة الإدارة للمدير مع إحصائيات فورية وتحديث حالات الطلبات.
